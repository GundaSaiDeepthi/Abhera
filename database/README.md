# Database Architecture - PostgreSQL

## Overview
PostgreSQL serves as the transactional and relational data store for the application.

## Core Schema Tables (To be implemented in Phase 2)
1. `sessions`: Tracks unique user sessions and generated `submission_id`.
2. `conversation_messages`: Stores all prompt exchanges and follow-up Q&A per `submission_id`.
3. `incidents`: Captures initial incident descriptions and combined narratives.
4. `predictions`: Multi-label BERT classification probability outputs (`DV`, `SH`, `ST`, `CA`, `WH`, `OV`).
5. `entities`: NER extracted entities (location, time, perpetrator details, evidence).
6. `questions`: Follow-up questions generated by the dynamic engine and user responses.
7. `reports`: Compiled final structured reports.
8. `laws`: Strict statutory legal knowledge base (imported from `data/laws.csv`).
9. `support_services`: Verified emergency contacts and support organizations (imported from `data/support_services.csv`).
