# Report API Technical Specification & Integration Guide

## 1. Overview & Purpose

The **Report API** exposes the underlying `ReportGeneratorService` via RESTful FastAPI endpoints. It allows frontend clients or internal services to trigger incident report generation and retrieve structured incident reports.

### Key Features
- **Anti-Hallucination Gated**: Legal and support sections are strictly validated against PostgreSQL `laws` and `support_services` database tables before response serialization.
- **Stateless/Stateful Hybrid**: Prefers taking a `submission_id` and retrieving stored submission, prediction, entity, and questionnaire data from PostgreSQL.
- **Idempotent / Upsert Persistence**: Repeated report generation requests for the same `submission_id` update the existing report record in PostgreSQL `reports` without creating duplicate rows.

---

## 2. API Endpoints Specification

### Endpoint 1: `POST /api/report/generate`

#### Purpose
Generates and persists a final structured incident report for a given `submission_id`.

- **Path**: `/api/report/generate`
- **Method**: `POST`
- **Content-Type**: `application/json`

#### Request Payload Schema (`ReportGenerateRequest`)
```json
{
    "submission_id": "SUB-12345678",
    "state": "Delhi",
    "district": "New Delhi"
}
```

#### Optional Fields (for manual override or testing):
- `narrative_text` (string): Override narrative text
- `bert_results` (object/array): Override predicted labels (e.g., `["DV", "WH"]`)
- `ner_entities` (array): Override extracted entity list
- `user_answers` (array/object): Override questionnaire answers

---

### Endpoint 2: `GET /api/report/{submission_id}`

#### Purpose
Retrieves the generated structured incident report for a specified `submission_id`.

- **Path**: `/api/report/{submission_id}`
- **Method**: `GET`
- **Parameters**:
  - `submission_id` (path, string, required): Unique submission ID

---

## 4. Error Handling & HTTP Status Codes

| Status Code | Description | Payload Structure |
| :---: | :--- | :--- |
| **`200 OK`** | Report generated or retrieved successfully | Full `ReportResponse` JSON |
| **`400 Bad Request`** | Missing required `submission_id` or malformed request | `{"detail": "Field 'submission_id' is required."}` |
| **`404 Not Found`** | Submission or report for given ID does not exist | `{"detail": "Incident submission 'SUB-XXX' not found."}` |
| **`500 Internal Error`** | Internal processing exception | `{"detail": "An internal error occurred while generating the incident report."}` |

*Security Notice: Error messages sanitize database credentials, stack traces, and internal filesystem paths.*
